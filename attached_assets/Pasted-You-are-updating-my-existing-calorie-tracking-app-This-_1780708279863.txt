1. NET CALORIES CAN GO NEGATIVE
   ====================================================

Currently, the app may prevent totals from going below 0.

Change this only for Net Calories.

Daily net calories should be:

Net Calories = Total Consumed Calories - Calories Burned

If burned calories are higher than consumed calories, net calories should be allowed to display as a negative number.

Example:

Consumed: 800 kcal
Burned: 950 kcal
Net: -150 kcal

Important:

* Total Consumed should still control the main calorie circle.
* Calorie color ranges should still be based on Total Consumed.
* Only Net Calories should be allowed to go negative.

====================================================
2. OPTIONAL GRADING SYSTEM
==========================

Add a new optional grading system.

This should be disabled by default and enabled in Settings.

Settings should include:

Grading System

* Enable Grading: On/Off
* Ideal Calorie Goal Range

  * Minimum goal calories
  * Maximum goal calories
* Grade Scale Settings
* Grade Color Settings
* No Data Day handling

The grade should be based on TOTAL CONSUMED CALORIES only.

Do not base the grade on net calories.

Reason:
Burned calories can affect net calories, but the grading system is meant to judge how close the user’s consumed calories were to their personal goal range.

====================================================
3. IDEAL GOAL RANGE = BEST GRADE
================================

Do not make “lowest calories = best grade.”

Instead, the best grade should be based on the user’s ideal calorie goal range.

Example:

Ideal goal range:
1600–2000 calories

If the user eats within that range, they should receive the best score/grade.

Default behavior:

* Inside goal range = 100% / A+
* Slightly outside goal range = lower grade
* Far outside goal range = much lower grade

This is more realistic and healthier than rewarding extremely low calories.

====================================================
4. DEFAULT SCORE CALCULATION
============================

Use this default scoring logic:

If total consumed is within the goal range:
score = 100

If total consumed is below the goal minimum:
deviationPercent = ((goalMin - totalConsumed) / goalMin) * 100

If total consumed is above the goal maximum:
deviationPercent = ((totalConsumed - goalMax) / goalMax) * 100

Then:

score = 100 - (deviationPercent * strictnessMultiplier)

Default strictnessMultiplier:
2

Clamp score between 0 and 100.

Example:
Goal range: 1600–2000
Consumed: 1440
This is 10% below 1600.
Score = 100 - 20 = 80%

Score: 80%
Grade: B-

Make the strictness customizable in Settings if reasonable, but keep it simple. It can be a dropdown:

* Lenient
* Normal
* Strict

Suggested multipliers:

* Lenient: 1.5
* Normal: 2
* Strict: 2.5

Default:
Normal

7. DAILY GRADE REPORTS
======================

Daily grade reports should only become available after the day is complete.

A day is considered complete at:

12:30 AM local time the next day.

Example:
The grade report for June 5 becomes available on June 6 at 12:30 AM.

Before the report is available, show:

“Today’s grade report will be available at 12:30 AM.”

or for yesterday before 12:30 AM:

“This grade report will be available at 12:30 AM.”

Each daily grade report should show:

* Date
* Total consumed calories
* Goal calorie range
* Score percentage
* Letter grade
* Grade color
* Short summary message
* Whether the user was under, inside, or over their goal range

Example:

Daily Grade Report
Friday, June 5

Consumed: 1,850 kcal
Goal Range: 1,600–2,000 kcal
Score: 100%
Grade: A+

Summary:
“You landed inside your goal range.”

8. REPORT GENERATION LOGIC
==========================

Reports should be generated automatically when the app opens or refreshes.

Create a function like:

generateDueGradeReports()

Logic:

* Check all tracked dates.
* For each date, calculate when the report becomes available.
* reportAvailableAt = selected date + 1 day at 12:30 AM local time
* If current time is after reportAvailableAt, generate the report.
* If a report already exists, do not duplicate it.
* If entries changed after the report was created, recalculate the report after confirmation.

Store reports locally.

Suggested daily report structure:

{
id,
date: "YYYY-MM-DD",
totalConsumed: 1850,
goalMin: 1600,
goalMax: 2000,
score: 100,
grade: "A+",
gradeColor: "#22c55e",
status: "inside_goal",
summary: "You landed inside your goal range.",
createdAt,
updatedAt,
wasRecalculated: false
}

10. EDITING PAST DAYS RECALCULATES REPORTS
==========================================

If the user edits a past day that already has a grade report, warn them before applying the change.

Warning text:

“Warning: This day already has a grade report. Editing this day will recalculate the daily grade and may also update the weekly grade. Are you sure you want to continue?”

This warning should appear when changing a past day by:

* Adding entries
* Deleting entries
* Editing entries
* Adding burned calories
* Adding meal entries
* Adding saved items
* Duplicating entries into that day

If the user confirms:

* Apply the change.
* Recalculate that day’s report.
* Recalculate the weekly report if that day belongs to a completed week.

If the user cancels:

* Do not apply the change.

11. WEEKLY GRADE REPORTS
========================

Add weekly grade reports.

Weekly grade should be based on the average of the 7 daily percentage scores.

Formula:

Weekly Score = average of daily report scores

Then convert that weekly score into the same letter grade scale.

Default week format:
Use Sunday through Saturday, unless the app already has a different calendar convention.

Weekly report becomes available after the final day of that week has a completed daily grade report.

Example:
If the week is Sunday–Saturday, the weekly report becomes available Sunday at 12:30 AM after Saturday ends.

Weekly report should show:

* Week date range
* Each daily grade
* Average score
* Weekly letter grade
* Summary message

Example:

Weekly Grade Report
June 1 – June 7

Daily Grades:
Sun: A
Mon: B+
Tue: A-
Wed: C
Thu: A+
Fri: B
Sat: A

Weekly Score: 89%
Weekly Grade: B+
